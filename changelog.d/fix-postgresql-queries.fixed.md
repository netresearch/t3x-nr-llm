- Five queries that failed on PostgreSQL work there now. The indexed_search retrieval backend lost every search ("missing FROM-clause entry for table ig"), because the query builder quoted its table aliases in some places and not in others; the aliases are now lower case. The page tree of a batch and the user budget windows compared a column with `PHP_INT_MAX`, which PostgreSQL refuses for an integer column; the doktype bound is now left out when there is none, and an unset budget window counts from after the upper bound. A uid outside the 32-bit range from a request (for example toggling a model or provider) is now "not found" instead of a database error, for every domain repository. A second projection of the same A2A task revision no longer aborts the whole transaction on PostgreSQL: the event insert runs in a savepoint ([#1420](https://github.com/netresearch/t3x-nr-llm/issues/1420)).
