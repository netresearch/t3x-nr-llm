- The scope of an assignment now judges a discard and a publish by what they change, not only by the draft the command names. A discard hard-deletes the draft and leaves nothing to read afterwards, so a discard of a draft whose live row lay outside the scope was committed when the draft itself lay inside it, and the drafts core discards along with a record (its translations, inline children, and the new pages and records below a new page) were never judged. Each discard core carries out, including the drafts it discards along with a record, and each publish is now judged right before core runs it: the live row at its live position and the draft at its position in the workspace both have to lie in the scope, and a row that cannot be read counts as outside it. A violation, a `version` action that neither core nor the workspaces extension knows, or a command whose key a later hook replaced with something other than one uid (on TYPO3 13.4 a stage change reads a list of uids from it), rolls the call back. A publish that took place and a stage change are now listed in the call's change list as updates (ADR-295, [#1442](https://github.com/netresearch/t3x-nr-llm/issues/1442)).
