- **Optional revision of a DeepL translation by a language model (ADR-233).** `TranslationOptions::withPolish(bool $enabled = true, ?string $instruction = null)` asks `TranslationService::translateWithTranslator()` and `translateBatchWithTranslator()` to let a language model revise the result for fluency, terminology and tone when the translator that ran is not the LLM translator. The revision runs on the default configuration or the pinned provider and model, through the budget pre-flight, and is recorded as a `translation_polish` usage row with the caller's extension next to its chat row with the tokens and cost; neither counts as a request, so a polished translation is still one request. It keeps tags, placeholders and glossary terms: when the answer changes them, is empty or cut off, or the call fails or is refused by the budget, the first translation is returned and `metadata['polish']['reason']` says why — the translation never fails because of the revision. `TranslatorResult::isPolished()` reports whether it applied; `translator` stays the first-pass translator. With `withCacheTtl()`, a requested revision is part of the cache key and a result whose revision did not apply is not stored. Off by default. `TranslationService`'s constructor gains an optional trailing `TranslationPolisher`; positional callers are unaffected.
