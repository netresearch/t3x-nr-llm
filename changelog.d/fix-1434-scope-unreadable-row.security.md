- The scope of an assignment no longer clears a call whose delete or undelete it could not read. When the read of the record's row, or of the draft version of a live row, failed and the call's history named nothing, the effect check left the command out and committed the call without judging it. A failed read now makes the call not judgeable, so it is rolled back, and the call's change list counts the record as not listed; a delete of a uid that no row bears is still no change. A delete that core makes live from a workspace that allows live editing, on a table without versioning, is now judged too; it was taken as a delete that did not happen (ADR-295, [#1434](https://github.com/netresearch/t3x-nr-llm/issues/1434)).
