- During 0.x the middle version number rises only for a breaking change: a breaking diff of the frozen `@api` surface or a behaviour change consumers have to handle, marked by a top-level CHANGELOG bullet that opens with `- **BREAKING`. A new method on an `@api` interface, a new public or protected abstract method on an `@api` abstract class, a new case of an `@api` enum, a changed `extends` and a removed `implements` count as breaking, and the API snapshot test now says so; the snapshot records `abstract class`, `method abstract` and the parents and implemented interfaces in each header line. Features, fixes and additive database changes raise only the last number, so `^0.55` keeps admitting them and dependent extensions no longer have to widen their constraint for every release. `composer ci:test:changelog:sections` refuses a release whose middle number disagrees with its `- **BREAKING` bullets or rises by more than one, and any other bold form of the word ([Stability](Documentation/Api/Stability.rst)).
