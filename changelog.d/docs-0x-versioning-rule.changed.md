- During 0.x the middle version number rises only for a change consumers have to act on: an incompatible diff of the frozen `@api` surface or a behaviour change they have to handle, marked by a top-level CHANGELOG bullet that opens with `- **BREAKING`. A new method on an `@api` interface, a new public or protected abstract method on an `@api` abstract class, a new case of an `@api` enum, a changed `extends` and a removed `implements` count as such a change, and the API snapshot test now says so; the snapshot records `abstract class`, `method abstract` and the parents and implemented interfaces in each header line. Features, fixes and additive database changes raise only the last number, so `^0.55` keeps admitting them and dependent extensions no longer have to widen their constraint for every release. `composer ci:test:changelog:sections` refuses a release whose middle number disagrees with its `- **BREAKING` bullets or rises by more than one, a release heading other than `## [N.N.N]`, and the word `breaking` anywhere in a release, in `[Unreleased]` or in a fragment except on such a marker line ([Stability](Documentation/Api/Stability.rst)).
