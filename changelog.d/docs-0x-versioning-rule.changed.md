- During 0.x the middle version number rises only for a breaking change: a breaking diff of the frozen `@api` surface or a behaviour change consumers have to handle, marked by a top-level CHANGELOG bullet that opens with `- **BREAKING`. A new method on an `@api` interface and a new case of an `@api` enum count as breaking, and the API snapshot test now says so. Features, fixes and additive database changes raise only the last number, so `^0.55` keeps admitting them and dependent extensions no longer have to widen their constraint for every release. `composer ci:test:changelog:sections` refuses a release whose middle number disagrees with its `- **BREAKING` bullets or rises by more than one, and any other bold form of the word ([Stability](Documentation/Api/Stability.rst)).
