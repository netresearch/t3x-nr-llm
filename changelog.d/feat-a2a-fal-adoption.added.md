- A2A server role: a run stores a file its client sent with the task in FAL (spec 051 A2A-FILE6, ADR-305), behind `a2a.files.enabled`. The tool `adopt_client_file` (group `files`, ships disabled, offered by a profile that may write) takes the number of the client's file and writes it only into the folder the publication profile names in the new field "Inbox folder for client files" (`fal_inbox_folder`, a combined identifier such as `2:/a2a-inbox/`); without a folder nothing is adopted. A public target (a storage marked public, a `Local` storage whose base path lies in the web root, or a storage without a record) is not stored when the profile is saved and is refused again at each call. The client's technical backend user writes, with its own file mounts and file permissions, and every call waits for the approval of a person of this installation; a call that cannot be written is refused before the approval is asked. A name already taken is never overwritten: the new file is renamed and the existing file keeps its bytes and its record. The file keeps the client's name without any path, with the extension of its checked type. Nothing references the adopted file; it takes effect only when an editor uses it in a workspace record. The task's `writes` artifact names the new `sys_file` record in workspace 0, because a table without workspace versions has only its live row.
