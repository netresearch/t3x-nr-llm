- A2A server role: a run sends a file from FAL with its task's result (spec 051 A2A-FILE6, ADR-284), behind `a2a.files.enabled`. The tool `send_fal_file` (group `files`, ships disabled) takes a `sys_file` uid and sends the file only when the task's publication profile approves its clients as recipients (the new field "Send FAL files to clients", read at each call) and the client's technical backend user reaches the file through its file mounts and file permissions (`FalStorageGate::isFileAccessible()`). A file outside those mounts, an unknown uid and a run without a user get the same answer. The file must be at most `a2a.maxRawPartBytes`, of one of the five types and pass that type's check; it goes out like every file a task sends, inline or as a protected download, and the model reads its id, never its content. Sending the same file again in a task adds nothing. While files are on, a skill that lists the tool and approves its clients lists the five file types among its output modes on the agent card. Taking a file a client sent into FAL is not offered.
