- A2A server role: inbound file parts (spec 051 stage 5c, ADR-284), switched off by default (`a2a.files.enabled`). A message may carry `raw` parts of `text/plain`, `application/json`, `application/pdf`, `image/png` and `image/jpeg` for a skill that lists the type among its input modes, and `url` parts from the hosts listed in `a2a.files.allowedHosts` (empty, the default, admits none): the URL passes the address guard when the task is accepted, and the worker fetches it before the run starts through the guard again, pinned, without credentials or cookies, following no redirect, and stores the checked copy, which is never fetched again; each file is checked against its type before it is stored, and archives, HTML, SVG and every other type are refused with `-32005`. `a2a.maxRawPartBytes` (default 5 MiB, at most 8 MiB, so that a sealed file fits into one database packet) bounds the decoded bytes of a file and of a message, with the base64 text measured before it is decoded (`-32602`). Files go into a private, sealed store (`tx_nrllm_a2a_file`), never into FAL; the worker checks a task's files against the list recorded at acceptance before the first model call and fails the task when one is gone, changed, unapproved or expired. The run receives text and JSON as text, an image as an image for a vision model, and a PDF as a line naming it. Files go with their task's run purge and after `a2a.files.retentionHours` (default 168) with `nrllm:privacy:purge`.
