- A2A server role: inbound file parts (spec 051 stage 5c, ADR-284), switched off by default (`a2a.files.enabled`). A message may carry `raw` parts of `text/plain`, `application/json`, `application/pdf`, `image/png` and `image/jpeg` for a skill that lists the type among its input modes, and `url` parts from the hosts listed in `a2a.files.allowedHosts` (empty, the default, admits none): the URL passes the address guard when the task is accepted, and the worker fetches it before the run starts through the guard again, pinned, without credentials or cookies, following no redirect, and stores the checked copy, which is never fetched again; each file is checked against its type before it is stored, but only after the skill, its input modes and the client's limits allow the message, and the images of one message may hold at most 16,777,216 pixels together, read from their headers before any is decoded (`-32602`; a fetched image beyond that fails the task), and archives, HTML, SVG and every other type are refused with `-32005`. `a2a.maxRawPartBytes` (default 5 MiB, at most 8 MiB, so that a sealed file fits into one database packet) bounds the decoded bytes of a file and of a message, with the base64 text measured before it is decoded (`-32602`). Files go into a private, sealed store (`tx_nrllm_a2a_file`), never into FAL; the worker checks a task's files against the list recorded at acceptance before the first model call and fails the task when one is gone, changed, unapproved or expired, or when files were switched off since the task was accepted. The run receives text and JSON as text, an image as an image for a vision model, and a PDF as a line naming it. When a task ends, its input files keep their record but lose their bytes and URL, and a `url` part not fetched yet is refused, so a fetch still running stores nothing. Files go with their task's run purge and after `a2a.files.retentionHours` (default 168) with `nrllm:privacy:purge`.
- A2A server role: files a task sends (spec 051 A2A-FILE5, ADR-284), behind `a2a.files.enabled`. When the run completes, each file the task registered becomes an artifact of its own: inline as `raw` while the files fit together into `a2a.maxInlineArtifactBytes` (default 256 KiB, at most 512 KiB), otherwise as a `url` to `<endpoint>/files/<file id>` below the A2A endpoint the task was accepted at. The download takes the client's bearer token, or a capability URL from `POST <endpoint>/files/<file id>/capability` that reads that one file of that one client for 15 minutes without the token; a capability URL is a transferable bearer right, and it stops working on expiry, a new client token or a disabled client. A failed capability is logged and counted per source address like a failed bearer token, under the same limit. The capability sits in the query string and can end up in the access logs in front of the endpoint. A file is served only while the task's artifacts, read at the run's current answer level, still name it, and an unknown, foreign or expired file answers 404. A run kept at the `redacted` level sends no file. Nothing produces such a file yet: the FAL export is not built.
